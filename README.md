# MarchLens

**从可见行军外观与玩家情报库，辅助判断对方可能使用的队伍。**

Windows / MuMu 本地测试版 **v0.6.1-beta.1**。识别七种兵种组合、读取敌方昵称，再展示你导入的候选阵容与战法。无需安装 Python，不需要购买模型 API。

[下载 Windows 测试版](https://github.com/mfoflife/MarchLens-Releases/releases)

本仓库用于发布软件下载与使用文档，不包含核心开发源码、原始训练权重或任何玩家情报库。**请下载 Releases 中的 Windows 软件包，不要下载 GitHub 自动生成的 Source code。**

> 当前仍为测试版。识别可能出错；唯一候选也不等于百分之百确认。测速暂不成熟，只展示试验结果，多支候选始终全部保留。

## 1. 下载安装

1. 打开本仓库右侧的 **Releases**，进入最新测试版。
2. 下载 `MarchLens-版本号-windows-x64.zip`。同页的 `.sha256` 文件是校验值，不是安装程序。
3. 将 ZIP **完整解压**到一个自己可写的目录，例如 `D:\Apps\MarchLens`。不要直接在压缩软件里双击运行；不要只复制一个 EXE。
4. 保留整个目录结构，双击根目录的 **MarchLens.exe**。

适用环境：64 位 Windows，桌面版 MuMu 模拟器，鼠标与键盘；建议 Windows 10/11、16 GB 内存。推理可使用 CPU，无需 NVIDIA 显卡。不同处理器、模拟器分辨率与内存占用会影响速度；尚未完成全部硬件组合认证。

软件包包含推理依赖和基础模型，体积较大。以 Release 标注的解压空间为准，额外留出采集录像空间。当前没有代码签名证书；若系统拦截，请先核对下载来源及校验值，不要关闭整机安全防护。

可选校验（PowerShell，在 ZIP 所在目录运行）：

```powershell
Get-FileHash -Algorithm SHA256 '.\MarchLens-0.6.1-beta.1-windows-x64.zip'
```

将 `Hash` 与同版本 `.sha256` 内的值逐字比较。解压后的 `MANIFEST.json` 列出包内文件校验值。

## 2. 首次启动与 MuMu 设置

1. 启动 MuMu，进入游戏的大地图。
2. 将游戏缩放调到 **满两格的默认视野**，采集与测速期间保持这个档位。
3. 保持 MuMu 可见，不要最小化、锁屏，避免其他窗口覆盖队伍与右侧面板。
4. 启动 MarchLens。等待控制台出现，首次模型加载可能较慢。
5. 控制台有三个标签：**实时监测、窗口与采集设置、打赏与交流**。
6. 点击 **详细结果网页**，打开本机工作台：`http://127.0.0.1:8766/intel`。

网页是本地程序的一部分，不是远程网站。软件运行时才能访问；无需开放路由器端口。每台电脑同一时间只运行一份 MarchLens。

首次使用没有情报数据是正常的。软件不附带作者或其他玩家的数据库，需要先导入自己的资料。

## 3. 准备你的情报库

### 3.1 Excel 直接导入

1. 网页左侧选择 **情报导入**。
2. 在 **Excel 直接导入**选择你的 `.xlsx` 文件，点击 **检查文件**。
3. 查看每个工作表的布局、表头行、字段对应关系，以及队伍预览。
4. 重点核对昵称、三名武将、兵种、等级、红度和战法。缺失信息显示未知，不应自动编造。
5. 如有映射错误，调整列与字段的对应，再次 **检查文件**。无关工作表可选择跳过。
6. 单条记录不应导入时，勾选 **本次不导入这条**；兵种识别有误时可在预览中修正并保存。
7. 确认预览内容后点击 **确认入库**。有解析错误时先修正；明确允许部分导入才选择相应选项。
8. 回到桌面控制台，在 **情报来源**选择新库。来源列表会自动刷新，也可点 **刷新来源**或按 F9，不需要重启。

支持一行一队、一个单元格包含队伍文字、逐武将行等布局，已验证多种导出形式；**不承诺任意 XLSX 都能无误识别**。文件名不同不代表新的资料；同一批次重复导入不会不断新增。

缺等级的队伍可以正常用于昵称＋兵种查询，但不进行依赖等级的速度估算。缺兵种不会凭武将名强行猜测组合。导入“缺项”不一定是失败，要区分原表未提供与字段映射错误。

### 3.2 用豆包网页解析后导入

1. 在 **AI 解析文件导入**下载 **豆包提示词 Markdown**。
2. 自行打开豆包网页，将提示词内容与原始 XLSX 一起提交，要求输出标准 JSON 文件。
3. 下载生成的 `.json`，回到 MarchLens 选择文件，点击 **检查 AI 解析文件**。
4. 核对预览，再点击 **确认豆包结果入库**。

这里由用户自行使用豆包，MarchLens 不自动连接豆包，不索取其账号。**向豆包上传原表会将该文件提供给第三方服务，请自行决定是否提供。** JSON 结构检查通过不等于内容正确；槽位、等级和昵称仍需对照源表检查。不要用截断的聊天文本冒充完整 JSON。

### 3.3 选择正确来源

网页顶部的情报来源和桌面控制台的情报来源都需要选对。查看网页某个库不等于桌面自动切换到了它。开始一次采集前，核对控制台当前来源名。切换来源影响后续采集，历史结果不会自动改库。

## 4. 首次配置引导

在 **窗口与采集设置**打开 **首次配置引导**，按顺序完成：

1. **选择窗口**：刷新窗口列表，选择当前 MuMu 游戏窗口。多开时不要选错实例。
2. **框选游戏画面**：优先自动检测并预览；不准确时手动框选。仅包含游戏显示区域，排除窗口标题、工具栏和黑边。拖动框选后按 Enter 保存，Esc 取消。
3. **框选外观**：先在游戏里选中一支行军队伍，待画面跟随其居中，框住中央完整部队外观。避免截掉马匹或士兵。
4. **框选昵称**：选中敌军后，框右侧敌军卡片上方的所属玩家昵称，不要框出发地、目的地、坐标或我方武将名字。
5. **连接 MuMu 触控（可选）**：使用 F6 净化需要 ADB。优先自动发现模拟器工具与设备；失败时在 MuMu 触控设置中选择其 ADB 程序和对应设备。多个设备时应核对实例，不能凭端口猜测。
6. **选择情报来源并自检**：运行 **环境自检**，按提示修正，再完成引导。

ADB 用于操作可见的地图筛选开关。普通屏幕采集并不读取游戏网络包。未配置好触控时先使用普通 F7 采集。

**修改模拟器尺寸、分辨率、显示缩放，或使用“MuMu 左右并排”后，请重新检查/框选区域。** 保持游戏内满两格视野不能替代屏幕区域校准。

## 5. 一次完整识别

1. 控制台选择正确的游戏窗口与情报来源，点击 **开始监听**。
2. 切回 MuMu，单击一支敌军，确认右侧出现所属玩家面板，队伍处在画面中心。
3. 普通模式可在有效短点击后自动采集，或按 **F7** 发起采集。
4. 使用净化时，先启用 **F6 净化采集 / 再按恢复**并配置好触控，然后选中敌军按 **F6**。程序切换地图显示、保留选中目标并采集。
5. 默认采集约 **3 秒**，期间不要拖动地图、切换部队或遮住窗口。控制台的进度条与秒数会变化，录制结束后继续等待分析。
6. 在悬浮状态条、F9 控制台或网页 **实时监测**查看结果：玩家昵称 → 兵种组合 → 候选队伍与战法。
7. 使用过净化时，**再次按 F6 恢复显示**，再选择下一支敌军。

净化会管理我军、友军、敌军及相关行军线的显示状态，恢复依据操作前状态。若中途异常，请切回 MuMu 按 F6 尝试恢复；仍未恢复时从游戏地图信息筛选菜单手动打开需要的项目。

录制 3 秒不等于 3 秒内显示全部结果：OCR、外观推理、必要的高分辨率复核还需要时间。没有选中敌军、面板未展开或游戏不在前台时，程序可能拒绝采集并显示原因。

## 6. 快捷键

| 按键 | 用途 | 使用条件 |
| --- | --- | --- |
| F6 | 净化并采集；再次按下恢复地图显示 | 已开始监听、MuMu 触控可用，切回所选游戏窗口 |
| F7 | 手动采集当前选中的队伍 | 已开始监听，所选游戏窗口在前台 |
| F8 | 停止监听 | 停止采集，控制台保留结果 |
| F9 | 显示/隐藏控制台 | 监听期间使用；来源列表也会刷新 |
| F10 | 排除本次上一个外观结果，重新识别 | 已有可重试的采集记录；也可点对应按钮 |
| F11 | 显示当前玩家在所选库中的全部队伍 | 已识别或确认玩家，且选择了情报来源 |

部分笔记本需要同时按 Fn。模拟器、录屏软件或键盘驱动占用功能键时，可先使用控制台按钮。停止监听后，全局监听快捷键可能不再响应，直接操作控制台即可。

## 7. 结果、纠错与查询

**颜色含义**：武将名为红色，战法为蓝色。红色不是实锤或胜率承诺，也不代表测速已验证。

- **唯一匹配**：当前昵称＋兵种组合在所选资料库只有一个候选。
- **多个候选**：全部展示，不因试验测速删掉队伍。展开队伍卡片查看武将、战法与来源信息。
- **玩家已找到，但该组合没有候选**：可能是斯巴达/拆迁、资料库未录入或外观识别错误。
- **昵称待确认**：核对近似昵称候选，再用界面确认；不要只凭 OCR 分数认定正确。
- **玩家未找到**：检查来源、错字、特殊符号、空格与资料更新时间。

同一来源中完全相同的昵称合并展示；相近但不同的昵称不自动当成同一个人。完全重复队伍在查询时合并展示并保留来源依据。

### 外观结果不对

1. 确认队伍在外观框内、昵称属于同一目标，必要时先恢复显示再重新选中。
2. 按 **F10**或点 **排除并重识别**，针对当前采集素材重试并排除上一个结果；不是修改或重新训练模型，也不保证新结果正确。
3. 也可用当前兵种组合下拉框手动选择骑、步、弓、骑步、骑弓、步弓、骑步弓。
4. 素材不清楚时，回游戏按 F7 重新采集。

地图外观只代表兵种集合。弓骑弓、弓骑骑、骑骑弓均表现为“骑＋弓”，不能据此外推三名武将的实际站位。

### 手动查询与历史

在网页 **查询队伍库**输入昵称，可选兵种组合后点 **查询**；不限定组合可查看玩家全部已录入队伍。历史采集保留当时的识别结果和来源，库更新后不会自动重写过去的判断。

## 8. 截图与手动补录

### 单支队伍，战报双图录入

1. 打开控制台 **战报双图录入**，或网页 **队伍补录**。
2. 上传一张战报总览图（能看到所属玩家与双方阵容）。
3. 再上传**同一场、同一侧队伍**的战法/阵容详情图，三名武将及战法应完整可见。
4. 选择需要录入的左侧或右侧，点击 **OCR 识别两张图**。
5. 核对昵称候选，必要时点 **使用上行昵称 / 使用下行昵称**；检查武将、等级、兵种、红度与三个战法槽位，修正 OCR 错字。
6. 确认后点击 **确认以上信息并入库**。录入到当前所选来源；没有来源时按界面提示建立手工来源。

### 批量双图

在 **批量录入多支队伍**选择多组截图，使用相同编号配对，例如 `01_战报.png`＋`01_战法.png`、`02_战报.png`＋`02_战法.png`。点击 **检查配对并批量识别**，逐组核对与确认入库；可用 **本组结束后停止**停止后续任务。不要将两场不同战报配成一组。

### 手动添加

在 **手动添加队伍**填写玩家昵称、三名武将及对应兵种，已知等级和红度可一并填写，未知留空。点 **保存队伍**后重新查询核对。不要为启用测速随便填写等级。

## 9. 试验测速与参数

**测速功能暂不成熟，可以正常采集并显示试验数值，但不用于候选优先排序、排除或标红。** 一个人同组合有多队时全部展示；只有一个候选时通常没有必要追加测速。

在控制台/网页选择 **当前疾风营平均等级**，范围 0～10，默认 10。每级对应 2 点速度；桌面选中即保存，网页修改后点 **保存速度设置**。新采集使用新设置，历史结果需显式重算。

估算依据为 `80 + 队伍中最低的武将等级速度 + 疾风营等级×2`，单位为格/小时；暂按没有速度内政计算，同阵营/同兵种的战斗速度加成不计入行军。未知加点、属性版本等仍会带来偏差。普通行军与调动应选对：要塞等之间的调动速度为普通行军的 **3 倍**，不是三分之一。

有多个可估速候选时，可按界面提示追加试验测速录像（当前最长约 15 秒），保持目标、画面与视野稳定。缺等级、素材无效或运动估计失败时，可能不提供速度值；这不影响昵称与兵种查询。

高级用户可到 **备份恢复与诊断 → 测速标定向导**，选择录像并填写独立可核实的真实格/小时数。按向导提供拟合段与独立验证段；不能拿候选估算值证明自身准确。当前标定即使通过，也不改变“展示全部候选”的产品策略。

## 10. 删除、备份与迁移

### 删除旧情报库

1. 网页顶部选中要删除的情报来源，核对完整库名。
2. 进入 **情报导入 → 管理旧情报库 → 删除所选情报库**。
3. 确认框展示库名、昵称数、队伍数，明确包含该库里的手动补录。
4. 确认才执行删除。若确认期间数据发生变化，程序会要求重新查看并确认。

删除不可撤销，建议先备份。只删除所选库，不删其他库、原始 XLSX、截图录像或历史结果。正在进行的识别或既有结果可能仍展示删除前的内容，请从下一次采集验证。桌面来源列表会自动刷新；若当前来源被删除，会退回仅采集状态，请重新选择。

**仅撤销原始导入批次**是另一项操作：仅支持可撤销的新批次，存在后续手动补录时会阻止，避免一并删掉。删除库以后 SQLite 文件大小不一定立即缩小，但腾出的空间可被后续数据复用。

### 备份与恢复

1. 打开网页 **备份恢复与诊断**（`http://127.0.0.1:8766/tools`）。
2. 导出情报库备份，妥善保存 JSON。备份含你的玩家与队伍情报，请勿公开上传。
3. 新电脑/新版本选择备份文件，点 **预览恢复内容**，核对后 **确认恢复**。

备份不包含截图、录像、模型、本机框选/ADB 设置或字段映射规则。迁移电脑后需重新选择窗口和配置采集区域。需要保留全部历史时，退出软件后另外复制整个旧软件目录到私人备份位置。

## 11. 窗口与显示

- **MuMu 左右并排**：让模拟器与控制台并排，窄窗口按钮自动换行；移动/调整后重新检查框选。
- **显示/隐藏状态条**：控制深蓝色结果悬浮条；可设置置顶与透明度。
- **F9**：需要调整时展开控制台，识别时可收起。
- **详细结果网页**：适合阅读全部候选、战法、来源和历史。
- **打开采集目录**：查看本机保存的截图、录像与结果；这些内容可能含玩家昵称，分享前请检查。
- **采集秒数**：可按需调整 4、5、6、7、10 秒等，进度随设定变化。较长采集会增加素材与分析时间，不保证提高准确率。
- **情报来源**下拉：选择后核对下面显示的完整名称，避免长文件名截断导致选错。

## 12. 自诊断与常见问题

先运行软件目录的 **自检.cmd**，或网页维护页的 **运行自诊断**。自检使用临时合成素材检查环境，不会启动游戏监听，也不是识别准确率评测。

| 现象 | 处理方法 |
| --- | --- |
| 127.0.0.1 拒绝连接 | 确认软件已启动，重新点“详细结果网页”；它会检查本地服务。不要修改公网防火墙规则。 |

## 13. 退出、升级与卸载

1. 按 F8 停止监听；使用过净化时先恢复地图显示。
2. 关闭控制台。不要在写入/导入进行中强制结束进程。
3. 升级前导出情报备份，将新版本解压到**新目录**，完整保留旧目录以便回退；不要覆盖单个模型或核心文件。
4. 新版本导入备份，重新选择游戏窗口、来源与识别区域，测试一支队伍。
5. 不要同时启动新旧两份软件。回退时退出新版，再运行旧版；使用对应版本的备份。

当前不自动更新，也没有在线授权。卸载前备份自己的情报与素材，退出程序后删除软件解压目录即可。软件内生成的采集素材会占用空间，确认不再需要后可从自己的采集目录清理；不要删除随包提供的 `runtime`、`app`、`data/vision` 和 `data/ocr`。
